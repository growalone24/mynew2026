Visibility

You have two choices:

Private
Only you and people you authorize can see it.

For learning, I recommend Private if you're going to experiment with personal files.

⚠️ VERY IMPORTANT

You will see options such as:

☐ Add a README file
☐ Add .gitignore
☐ Choose a license
For THIS exercise:

Do NOT select any of them.

Leave them unchecked.

Why?

Because you already have a local Git repository. GitHub's documentation specifically recommends creating the new repository without initializing it with a README, license, or .gitignore when you're pushing an existing local repository, which avoids unnecessary merge conflicts.

So:

Repository name: my-first-project

Description: optional

Public/Private: your choice

☐ Add a README file       ← DON'T SELECT
☐ Add .gitignore          ← DON'T SELECT
☐ Choose a license        ← DON'T SELECT

Then click:

Create repository

Step 14

Push
 ↓

GitHub's documented flow uses git push -u origin main for this situation.

PART 13 — GitHub authentication

The first time you push using HTTPS, Git may ask:

Username for 'https://github.com':

Enter your GitHub username.

Then it may ask:

Password for 'https://YOUR_USERNAME@github.com':
⚠️ IMPORTANT

Do NOT enter your normal GitHub password.

GitHub removed password authentication for Git operations over HTTPS. Use a Personal Access Token (PAT) instead.

PART 14 — Create a Personal Access Token

If you don't already have one:

Go to your GitHub account:

Settings → Developer settings → Personal access tokens

GitHub currently provides token options such as fine-grained personal access tokens.

Create a token with access to the repository you're pushing to.

For a simple personal learning repository, give it the minimum repository access necessary to push to that repository.

⚠️ Never send your token to me or anyone else.

When Git asks:

Password:

Paste the token.

Nothing may appear on the screen while you paste/type the token. That's normal.

Press:

Enter
